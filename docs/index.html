The part most projects leave out

We audited our own accuracy, and published what we found.

Fake-news classifiers routinely report 99% accuracy. That number comes from artifacts in the training scrape, not from any ability to detect deception. So we measured ours three ways — including the one that hurts.

In the classic Kaggle dataset, 81% of the “real” articles open with a wire-service dateline that no fake article has. A model can hit 99% by learning “does this look like Reuters” — and learn nothing about truth at all.

Ten signals · weights sum to 1.00

Because the classifier can’t be trusted alone, the score shows its reasons.

Every signal is something you can check by eye. The manipulation score is a plain weighted sum of the ones that triggered — no single detector can push it past 0.20 on its own, and nothing is hidden behind the number.

clickbait_terms

Curiosity-gap phrasing: “you won’t believe”, “what happens next”, “shocking”.

Half model, half arithmetic you can check

Where the number actually comes from.

The score is not the classifier’s opinion. It is a fixed blend: half the model’s probability, half the weighted sum of the signals that triggered. The blend is deliberate — it stops a confident-but-wrong classifier from running away with the verdict, and it keeps most of the number itemized on screen.

score = round( 100 × ( 0.5 × Pmodel(fake) + 0.5 × Σ wtriggered ) )
Model probability
0.97

TF-IDF over a 60k-article corpus into logistic regression. Opaque by nature, and measurably weak off its training distribution — which is exactly why it only gets half a vote.

Two steps, about five minutes

Run it locally.

1 · Start the stack

# from the repo root — creates the venv on first run
./run

One command brings up the analysis API on port 8000 and this landing page on port 8080, waits for the API to answer /health, and tells you whether the real model or the labeled stub loaded. Ctrl+C stops both.

Prefer to drive it yourself: 

cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

The trained model and vectorizer live in backend/artifacts/. If they are missing the server still starts, using a clearly-labeled stub so the whole pipeline stays testable.

2 · Load the extension

  1. Open chrome://extensions and turn on Developer mode.
  2. Click Load unpacked and pick the extension/ folder.
  3. Open any news article, click the icon, then Analyze this page.
  4. Optionally click Highlight patterns on page to mark the flagged sentences in place.
# sanity check the API on its own
curl -s localhost:8000/health

The questions worth asking first

What it does, and what it refuses to do.

Does a high score mean the article is false?

No. The score measures how the piece is written, not whether its claims hold up. Careful propaganda can be written in flawless wire style and score low; an honest local report can be loud, badly edited, and score high.

Treat a high score as “this text is working hard on your emotions” — a prompt to check the sourcing yourself, not a verdict.

Does anything I read get uploaded?

No. The content script reads the article out of the tab you are already on and posts it to 127.0.0.1:8000 — a server running on your own machine. There is no hosted backend and no analytics.

The manifest asks for exactly two permissions, activeTab and scripting, and its only host permissions are localhost:8000 and 127.0.0.1:8000. It cannot reach anywhere else even if it wanted to.

Why publish a 52% number? It makes the project look worse.

Because it is the honest one. Trained and tested inside a single scrape, the model scores in the nineties — largely by learning which collection an article came from. Move it to a different collection and that shortcut disappears.

Publishing only the flattering number would have made the tool look like a lie detector. It is not one, and the whole design — half the score coming from signals you can verify by eye — follows from admitting that.

What if I haven’t trained a model yet?

The server starts anyway, using a clearly-labeled stub so the whole pipeline stays testable end to end. The API returns model_is_stub: true and the popup shows a warning banner, so a stub score can never be mistaken for a real one.

Drop model.pkl and vectorizer.pkl into backend/artifacts/ — or point MODEL_PATH and VECTORIZER_PATH elsewhere — and restart.

Can I retrain it on my own corpus?

Yes. backend/train.py fits the vectorizer and classifier, and backend/textclean.py holds the preprocessing. Both training and serving import the same clean_text, so the two sides cannot quietly drift apart — a mismatch there is the classic way a model that scored well in a notebook starts returning nonsense in production.

Which browsers does the extension run in?

It is a Manifest V3 extension, loaded unpacked, and it has been used and tested in Chrome. Other Chromium browsers such as Edge and Brave use the same extension format, but they have not been tested here.

Read this before you trust a score

This tool flags stylistic manipulation patterns, not factual accuracy. A low score does not mean an article is true, and a high score does not mean it is false. Careful propaganda can be written in flawless wire style, and honest local reporting can be loud and badly edited.

Treat it as a reading aid that names the techniques in front of you — a media-literacy instrument, not a verdict.

A high score says

  • This piece leans on shouting, curiosity gaps or rhetorical questions.
  • It quotes few named people, or none at all.
  • It reads as opinion where you would expect description.
  • Worth checking who is making these claims, and on what evidence.

A high score does not say

  • The claims in the article are false.
  • The outlet is untrustworthy.
  • A low-scoring article is therefore true.
  • Anything at all about the facts. It has not checked one.
